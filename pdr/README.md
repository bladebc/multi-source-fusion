# PDR 定位器（实验②）

行人航位推算（Pedestrian Dead Reckoning）：用手机的加速度计、陀螺仪、磁力计，算出「走了多少步、每步多远、朝哪走」，
再把每一步首尾相接，画成轨迹。

```
位置 = 起点 + Σ 每步（步长 × 方向）
```

输入就是 `android-app/` 导出的 ZIP，不用解压。

## 快速开始

```sh
cd pdr
uv run python run_pdr.py ../data/<会话>.zip --calib 5 80 100   # 5–80 s 内沿直线走了 100 m，用这段标定步长
```

输出 `out/<会话>/out_pdr.png`，左图是轨迹（三种航向源对比），右图是航向随时间的变化。终端会打印步数、里程和标定出的 K。

`--calib` 不填时用默认 K = 0.52（课件锚数据的值），**每个人的步态都不一样，建议标定**。
其他参数：`--alpha` 互补滤波系数（默认 0.98），`--model const` 改用恒定 0.75 m 步长，`--static` 开头静止秒数（默认 3）。

## 算法要点

1. **步检**：|a−g| → 0.18 s 滑动平均 → 峰值高于 0.9 × 均值（且 ≥ 1.2 m/s²）→ 两峰间隔 ≥ 0.3 s。重力用 1 s 滑动均值估计后减掉。
2. **步长**：Weinberg 模型 `L = K · ⁴√(峰 − 谷)`，峰谷在平滑后的 |a| 上取；走一段已知距离 D，由 `K = D / Σ⁴√(峰−谷)` 标定。
3. **航向**：磁力计用加速度计做倾角补偿，得到磁航向（与 Android `getRotationMatrix` 同一套几何）；陀螺仪先**投影到竖直方向**再积分，
   所以手机斜着拿也能正确算转弯；两者用互补滤波融合：`ψ ← α(ψ + ω·Δt) + (1−α)ψ_mag`。
4. **位置**：x += L·sin ψ（东），y += L·cos ψ（北），ψ 从正北顺时针量。

**注意**：α 的含义取决于更新频率，时间常数 τ ≈ Δt·α/(1−α)。这里每个采样点（50 Hz）更新一次，α = 0.98 只相当于 τ ≈ 1 s；
课件里说「α = 0.98，约 1 分钟」，那是按每步更新一次算的。报告里写 α 时要一并写清更新频率。

## 验证情况

| 验证 | 结果 |
|---|---|
| 课件锚数据复现（`run_anchor.py`） | 快走段 382 步（课件 377；网站数据由 100 Hz 降到了 50 Hz）、阈值 1.86（课件 1.86）、K = 0.54（课件 0.52）、里程 286 m（课件 283 m） |
| 仿真全链（`sim.py` + `run_pdr.py data/sim`） | 真值 171 步 / 120.2 m → 检出 159 步，标定 K = 0.510（真值 0.50），终点误差：纯陀螺 19.0 m、纯磁力计 7.7 m、互补 7.7 m |
| 仿真手机斜拿 50° | 结果与平放完全一致；如果不做竖直投影、直接用陀螺 z 轴，纯陀螺终点误差会变成 66.6 m |

## 采集协议（给 `run_pdr.py` 用）

全程手机**平端在胸前，屏幕朝上，顶部朝向前进方向，握法不要变**；每段开头和结尾各**静止 5 s**（用于初始对准）。

| 段 | 怎么走 | 用途 |
|---|---|---|
| A 直线标定 | 沿已知长度的直线走（如操场直道 100 m） | `--calib` 标定 K |
| B 闭合一圈 | 绕一圈回到起点 | 起点即终点，终点偏移 = 闭合误差 |
| C 走廊 60 s | 楼内走廊，拐几个弯 | 模拟期中现场验收 |
