# 实施计划与维护规则

更新日期：2026-10-06。本文是项目计划，不是课程额外要求，也不表示已自动启动全部开发。

## 第一阶段：补采集证据

- [ ] 真机验证 APK 1.1：采集、锁屏长时记录、停止保存、ZIP 导出与文件选择器页面重建恢复。
- [ ] 在室外取得有效 GNSS，再采教学楼场景，记录环境与提供者。
- [ ] 完成 40 秒预演和操场 10 分钟试采；保留波形及质量结果。
- [ ] 按第 6 次课要求准备自采 20 分钟数据；先确认是否允许多段拼接。
- [ ] 完成课程入库流程并保留凭据；不得未经授权自动上传位置数据。

交付物：原始 ZIP、采集说明、质检表、截图与入库证明。更新 [实验状态](experiment-status.md)。

## 第二阶段：Android 实时 PDR

- [ ] 将步检、步长、航向与位置更新迁入 Android，明确手机坐标、单位和航向符号。
- [ ] 实时绘制轨迹，显示步数、里程、参数和质量状态。
- [ ] 处理初始静止对准、断流与传感器不可用，保留原始记录。
- [ ] 与 Python 对同一输入比较关键输出，确认移植一致性；实时算法须因果运行，不直接照搬离线居中滑窗。
- [ ] 完成走廊 60 秒实走投屏与独立终点误差测量。

交付物：可安装 APK、复跑说明、关键验证结果、演示视频或截图。实时轨迹是已确认的课程要求，不再列为待确认。

## 第三阶段：独立评估与报告

- [ ] 使用与标定不同的数据检查步数、距离和航向误差。
- [ ] 建议增加闭合路线，检查终点漂移；记录不同场景的参数适用边界。
- [ ] 输出峰标记波形、轨迹和参数表。
- [ ] 整理参数理由、误差分析、改进路线三件套，准备 3 分钟讲解。
- [ ] 记录提交和验收结果；后续 KF / DL 留到相应课程阶段。

## 文档维护规则

1. 课程要求变化时更新 [课程路线](course-overview.md) 和 [验收规范](acceptance.md)，记录日期、来源页及变化内容。
2. 完成任务后更新 [实验状态](experiment-status.md) 与本页勾选，并链接到具体文件、提交、运行结果或验收凭据。
3. 采集或分析参数变化时更新 [数据规范](data-protocol.md) 与相关模块 README。不要重复复制整份技术说明。
4. 记录“实测”“历史作者记录”“仿真”“推断”的区别；未经复跑的旧指标不升格为本次验证。
5. 实验状态以证据为准；构建成功、PR 合并、Release 发布都不自动意味着真机验收或课程完成。
6. 文档使用仓库相对 Markdown 链接；提交前检查链接目标和 `git diff --check`。本目录不存签名密钥、令牌或私人账号凭据。
