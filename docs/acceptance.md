# 验收与报告规范

## 实验②的明确验收要求

第 6 次课的验收页明确要求 Android 端自采数据，第 8 次课末现场演示和报告。以下不是可选的 Python 离线替代流程。

演示：

- [ ] 走廊实走 60 秒，Android 端实时产生轨迹并投屏。
- [ ] 口头汇报终点误差量级，注明测量方法与缺失证据；精度不作硬指标，诚实汇报。
- [ ] 用 3 分钟讲清参数如何选择。

报告：

- [ ] 参数选择及理由：α、K、阈值，以及对应更新频率、信号与数据段。
- [ ] 误差分析：里程、航向、修正三类问题。
- [ ] 下一步改进路线：对应实测问题，区分必做修复与进阶功能。

评分构成：现场演示 40、报告 40、代码规范 20；代码规范包含接口一致、注释及可复跑。课件强调自采数据、代码自写；允许使用 Mahony 等轮子但要标注边界。本项目应如实说明 AI 辅助与开源依赖，AI 辅助是否满足教师对“自写”的具体认定需确认，不自行宣布满足诚信条款。[来源：第 6 次课“验收口径”](http://10.112.165.210:9000/multi_source_fusion/lesson04_pdr/slides.html)

## 算法与接口

课件发放的核心接口为：

```python
def detect_steps(acc_mag, fs=100) -> list[float]: ...
def step_length(peak_val, valley_val) -> float: ...
def heading_update(psi, gyro_z, mag_az, dt, alpha=0.98) -> float: ...
```

位置更新沿航向累计步长。当前 Python 保持这三个基本入口并扩展可配置参数；Android 移植时保留对应职责和单位约定。航向可用互补滤波或进阶替换 Mahony；不能据此把 Mahony 判为基础必做项。[来源：第 6 次课“接口发放”](http://10.112.165.210:9000/multi_source_fusion/lesson04_pdr/slides.html)
