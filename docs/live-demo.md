# 实时轨迹与现场投屏方案

方案日期：2026-10-06。当前为设计与准备说明，未实施 Android 实时 PDR，未进行手机投屏测试。本机有 Homebrew 和 Android SDK / ADB；当前未发现 `scrcpy` 可执行文件，ADB 无连接设备。

## 推荐链路

```text
手机 IMU → Android 实时 PDR → App 轨迹演示页
                                    ↓ 屏幕镜像
                            scrcpy → Mac → 投影仪
```

计算、画轨迹、保存数据都在手机上；电脑负责镜像和展示。这样可以满足课程明确的 Android 端要求，镜像断线也不应导致采集和 PDR 停止。网络仅用于屏幕传输，不作为轨迹计算前提。

需要分别完成两项工作：实时 PDR 页面，以及现场投屏。现有 APK 1.1 只有采集与波形，直接镜像它还不能演示实时轨迹。

## Android 页面与算法建议

以下为项目设计建议，不是课件规定的 UI 或性能指标。

演示页以米制平面轨迹为主，显示起点、当前点、北向标识和比例尺；同时显示步数、累计里程、已用时间、航向与当前参数。轨迹区域应占主要面积，关键指标使用投影可辨认字号；不依赖室内 GNSS 或在线地图。

- 开始前固定持机姿态，完成静止对准；由参数页预设 K、α 和检测参数。
- 使用原始事件时间戳更新状态，单位和陀螺航向符号与离线工具对应。
- 采用有限缓存和因果滤波；步峰确认可以有短延迟。离线居中滑窗使用未来样本，不能直接宣称已实时移植。
- 区分传感器处理、轨迹状态与 UI 绘制；IMU 请求约 50 Hz，UI 建议约 10–20 次/秒更新，不要求每条 IMU 事件重绘。
- 断流或传感器不可用时显示质量状态，禁止补出虚假运动；投屏断开不影响本地记录。
- 单独提供 60 秒演示流程：记录完整准备 / 静止 / 实走阶段，明确哪 60 秒属于实走；结束显示结果并导出原始 ZIP。当前 App 的“手动 / 40 秒预演 / 10 分钟步行”模式尚未覆盖这一专用流程。

验收误差仍需真实终点位置或独立路线测量。闭合路线可比较估计终点与起点，但是否适用现场路线需事先协调。界面有“终点位移”不能自动当作“终点误差”。

## scrcpy 投屏

scrcpy 官方支持 USB 与 TCP/IP 屏幕镜像，支持 macOS。建议 USB 用于安装、授权和近距离调试，无线用于走廊 60 秒实走。[官方项目](https://github.com/Genymobile/scrcpy)

Mac 安装步骤（尚未执行）：

```sh
brew install scrcpy
```

本机已有 Android SDK 的 ADB。若 `adb` 不在 PATH，可在运行命令的终端先配置：

```sh
export PATH="/Users/bladeBC/Library/Android/sdk/platform-tools:$PATH"
adb devices -l
```

开启手机 USB 调试，插入数据线并接受电脑授权；`adb devices -l` 必须显示 `device`，而非 `unauthorized`。先验证 USB 镜像：

```sh
scrcpy --select-usb --no-audio --max-size=1280 --max-fps=30
```

手机和电脑连接同一可互通 Wi-Fi，USB 保持连接，再运行：

```sh
scrcpy --tcpip --no-audio --max-size=1280 --max-fps=30 --record=demo-60s.mp4
```

`--tcpip` 可自动启用并连接网络调试；确认无线画面正常后拔掉 USB，在实际走廊范围预演。Android 11 及更新设备也可通过无线调试配对，按设备实际菜单和端口操作。[连接文档](https://github.com/Genymobile/scrcpy/blob/master/doc/connection.md)

1280 / 30 fps 是项目起始配置，可按文字可读性与无线质量调整；它不改变 IMU 采样频率。[视频参数](https://github.com/Genymobile/scrcpy/blob/master/doc/video.md)

`--record` 保存镜像视频；上例关闭音频，不包含讲解声音。需要讲解记录时另做电脑录音或视频录制。录像是验收证据和故障备份，不可把录像回放当作现场实时演示。[录制文档](https://github.com/Genymobile/scrcpy/blob/master/doc/recording.md)

关闭镜像后，可执行 `adb disconnect` 并关闭手机无线 / TCP/IP 调试。只在自己的可信演示网络使用，不保留不必要的网络调试入口。

## 网络与投影准备

优先使用经过实测的同一 Wi-Fi 或专用热点；校园 Wi-Fi 的设备隔离和覆盖情况必须现场确认。可用另一台设备提供热点，再让 Mac 与采集手机同时接入。手机自己开热点是否可用要实测，不预设手机型号一定支持。

Mac 通过现场 HDMI / USB-C 转接器或场地已有连接接入投影仪，展示 scrcpy 窗口。连接和分辨率依场地确定；提前检查横竖屏、字体、窗口尺寸、电脑休眠及通知遮挡。两人协作较方便：一人持机实走，一人在电脑端观察和讲解。

## 备选方案

Android Studio 的 Running Devices 支持物理设备镜像，可作为已有工具的备用路径；无线调试与网络条件仍需检查，不能将其视为对无线覆盖问题的解决办法。[Android 官方说明](https://developer.android.com/studio/run/device)

USB 镜像适合台前调试，不适合固定投影电脑下的长距离走廊实走。若无线覆盖不够，应换经过验证的网络或与教师协调可覆盖的走廊路线。断网时手机继续本地记录，恢复后展示真实结果，并如实说明中断。
